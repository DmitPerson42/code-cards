# Code Cards - план разработки

Документ для передачи агенту-исполнителю. Все решения по функционалу здесь уже приняты
(см. раздел 2 и 3), его задача - реализовать, а не перепроектировать.

Дата составления: 11 ноября 2026.

---

## 1. Что это за приложение

Локальная библиотека фрагментов кода. Каждая карточка - фрагмент с разбором: что делает код
в целом и что делает каждая строка. Карточки группируются тегами и подборками.

Главная идея заимствована из системы чертежей Factorio: карточка - это не просто сохранённый
текст, а **шаблон с параметрами** (слотами), который можно "поставить" в проект несколько раз,
заполнив разные значения.

Второе назначение - база знаний для учёбы: код разбирается по строкам, чтобы через полгода
понять его за минуту.

### Три принципа (из них выводится всё остальное)

1. **Быстрое сохранение.** Вставить код и сохранить - два действия. Разбор и теги добираются
   позже. Если добавление сниппета медленнее, чем копирование в заметки, приложением
   перестают пользоваться.
2. **Повторное понимание.** При открытии карточки должно быть ясно не только что делает код,
   но и по каким строкам это видно.
3. **Полная автономность.** Нет ни одного сетевого запроса. Приложение работает без интернета,
   данные лежат на диске.

## 2. Пользовательские решения (уже согласованы, не менять)

| Вопрос | Решение |
|---|---|
| Источник кода | Пользователь вставляет код сам, источник любой |
| Блоки кода в карточке | Одна карточка - несколько блоков кода, у каждого свой разбор |
| Разбор | Свободный текст, привязанный к диапазону строк `from`-`to` |
| Правка кода | Умный перенос разбора по смыслу, изменённое помечается "устарело" |
| Теги | Свободные, без отдельных полей сложности, автодополнение из существующих |
| Сохранение | Вставил код - сразу сохранил; разбор и теги потом |
| Поиск | Название + теги + код + тексты разбора. Точные совпадения, без опечаток |
| Подборки | С вложенностью (дерево), ручной порядок карточками |
| Слоты | Необязательная фича, включается на карточке |
| Синтаксис слотов | `{{имя}}` по умолчанию, режим "не слоты" на отдельной карточке |
| Сделать чертёж из кода | Нужна кнопка, превращающая значения в слоты |
| Запуск | Tauri 2, настоящее окно-приложение |
| Тема | Тёмная по умолчанию, светлая в настройках |

## 3. Функциональная спецификация

### 3.1. Модель данных (SQLite)

Схема продумана с учётом всех решений, включая слоты и вложенные подборки. Менять её
без причины нельзя - на ней стоит миграция и экспорт.

```sql
-- Карточка
CREATE TABLE cards (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    title         TEXT NOT NULL,
    description   TEXT NOT NULL DEFAULT '',   -- что делает код в целом
    is_template   INTEGER NOT NULL DEFAULT 0, -- использует ли слоты
    slot_syntax   TEXT NOT NULL DEFAULT 'double_brace', -- double_brace | jinja_off
    created_at    TEXT NOT NULL,
    updated_at    TEXT NOT NULL,
    favorite      INTEGER NOT NULL DEFAULT 0,
    -- проверка актуальности: "последний раз проверено на версии"
    checked_version TEXT NOT NULL DEFAULT '',
    checked_at    TEXT NOT NULL DEFAULT ''
);

-- Блок кода внутри карточки (1..N)
CREATE TABLE code_blocks (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    card_id     INTEGER NOT NULL REFERENCES cards(id) ON DELETE CASCADE,
    language    TEXT NOT NULL DEFAULT 'python',
    code        TEXT NOT NULL DEFAULT '',
    sort_order  INTEGER NOT NULL DEFAULT 0
);

-- Разбор: свободный текст на диапазон строк блока
CREATE TABLE line_notes (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    block_id    INTEGER NOT NULL REFERENCES code_blocks(id) ON DELETE CASCADE,
    line_from   INTEGER NOT NULL,   -- 1-based
    line_to     INTEGER NOT NULL,
    text        TEXT NOT NULL,
    is_stale    INTEGER NOT NULL DEFAULT 0,  -- строки изменились после правки кода
    sort_order  INTEGER NOT NULL DEFAULT 0
);

-- Слоты шаблона
CREATE TABLE slots (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    block_id    INTEGER NOT NULL REFERENCES code_blocks(id) ON DELETE CASCADE,
    name        TEXT NOT NULL,
    default_value TEXT NOT NULL DEFAULT '',
    variants    TEXT NOT NULL DEFAULT '[]'  -- JSON-массив строк для выбора
);

-- Теги
CREATE TABLE tags (
    id    INTEGER PRIMARY KEY AUTOINCREMENT,
    name  TEXT NOT NULL UNIQUE COLLATE NOCASE,
    color TEXT NOT NULL DEFAULT ''
);

CREATE TABLE card_tags (
    card_id INTEGER NOT NULL REFERENCES cards(id) ON DELETE CASCADE,
    tag_id  INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (card_id, tag_id)
);

-- Подборки (дерево)
CREATE TABLE collections (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    name       TEXT NOT NULL,
    parent_id  INTEGER REFERENCES collections(id) ON DELETE CASCADE,
    sort_order INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL
);

CREATE TABLE collection_cards (
    collection_id INTEGER NOT NULL REFERENCES collections(id) ON DELETE CASCADE,
    card_id       INTEGER NOT NULL REFERENCES cards(id) ON DELETE CASCADE,
    sort_order    INTEGER NOT NULL DEFAULT 0,
    added_at      TEXT NOT NULL,
    PRIMARY KEY (collection_id, card_id)
);

-- Поиск (FTS5)
CREATE VIRTUAL TABLE card_search USING fts5(
    title, description, tags, code, notes,
    content='', tokenize='unicode61 remove_diacritics 2'
);

-- Метаданные схемы
CREATE TABLE schema_meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);
```

Индексы:
- `card_tags(tag_id)`;
- `line_notes(block_id, line_from)`;
- `collection_cards(card_id)`.

FTS5 наполняется вручную (external content, `content=''`) при каждом сохранении карточки:
пересобираем строку для `card_id`. Это проще и надёжнее, чем триггеры для составных полей.

### 3.2. Поиск

- Индексируются: название, описание, теги (через пробел), код всех блоков, тексты разбора.
- Поиск **точный**, без нечёткости.
- Нормализация запроса перед FTS: пользователь пишет `arr[0]` - пунктуация ищется отдельным
  проходом по коду (FTS её не индексирует). Алгоритм:
  1. разбить запрос на "слова" и "символьные куски" (всё, что вне `[\p{L}\p{N}]`);
  2. слова уходят в FTS как `MATCH` с префиксом `слово*`;
  3. символьные куски ищутся `LIKE '%arr[0]%'` по полю `code`;
  4. результаты объединяются по `card_id`.
- Фильтры комбинируются: теги (AND), язык, подборка, избранное.
- Подсветка совпадений в списке: возвращать сниппет через `snippet()` FTS5.

### 3.3. Экран карточки (главное)

Три состояния: **просмотр**, **редактирование**, **вставка в проект**.

**Просмотр:**
- слева код с нумерацией и подсветкой; справа колонка разбора;
- наведение и клик по строке подсвечивают соответствующий блок разбора и наоборот;
- сверху название, теги, описание;
- кнопки: "Копировать", "Заполнить слоты", "В подборку", "Редактировать", "Удалить".

**Редактирование:**
- title, описание;
- блоки кода: вкладки по блокам, CodeMirror 6, выбор языка, кнопка "+ ещё блок", удаление блока;
- рядом с кодом - редактор разбора: список диапазонов и текстов. Кнопка **"Разбить на строки"**
  создаёт пустые записи под каждую непустую строку и сразу фокусирует первую пустую;
- галочка "использует слоты". При включении подсвечивает найденные в коде `{{...}}` как
  слоты, имя редактируется на месте;
- кнопка **"Сделать чертёж из выделенного"**: выделяешь строку, нажимаешь, вводишь имя слота -
  выделенный текст в коде заменяется на `{{имя}}`, а исходное значение становится значением
  по умолчанию;
- поле тегов с автодополнением из существующих и мягким предупреждением о похожем теге:
  если есть `JS`, при вводе `js` - предложить существующий.

**Заполнение слотов:**
- список слотов с полями; значение по умолчанию подставлено;
- если у слота есть варианты - выпадающий список вместо поля ввода;
- результат в отдельной панели; кнопки "Копировать" и "Скопировать и закрыть".

### 3.4. Список карточек

- сетка карточек: название, язык, теги, первые 3-4 строки кода;
- поиск сверху (живой, с debounce 200 мс);
- панель слева: подборки (дерево), теги (с счётчиками), избранное;
- сортировка: недавние, по алфавиту, по дате создания;
- кнопка "Новая карточка" (Ctrl+N).

### 3.5. Правка кода и перенос разбора (критично)

После изменения кода блока при сохранении:

1. Строки старого и нового кода идут в `similar` (crate, алгоритм патчей).
2. Строится отображение старых номеров строк на новые.
3. Диапазоны `line_notes` переносятся:
   - если обе границы отобразились - перенос без пометки;
   - если одна граница потерялась - диапазон усекается, `is_stale = 1`;
   - если диапазон исчез полностью - `is_stale = 1`, запись не удаляется.
4. Перед сохранением пользователю показывается **сводка**: "сдвинуто: 4, изменено: 2,
   потеряно: 1", с возможностью отменить сохранение.
5. В редакторе устаревшие пояснения видны с бейджем "устарело" и цветной полосой слева.

Требование без исключений: **молча терять разбор запрещено.** Пункт 4 обязателен.

### 3.6. Резервные копии

- При запуске: если прошло больше суток с последнего бэкапа, копия базы в
  `backups/app-YYYYMMDD-HHMMSS.db`, хранится 10 последних, старые удаляются.
- Копия делается через `VACUUM INTO`, не копированием файла (в режиме WAL иначе
  получается неполная база).
- Кнопка "Экспорт в JSON": весь архив (карточки, блоки, разбор, слоты, теги, подборки) в
  один читаемый JSON.
- Кнопка "Импорт из JSON": влить архив. При совпадении `id` создать новые карточки, а не
  перезаписывать; показать отчёт о количестве.
- Кнопка "Экспорт карточки в Markdown": код плюс разбор таблицей.

### 3.7. Горячие клавиши

| Сочетание | Действие |
|---|---|
| Ctrl+N | Новая карточка |
| Ctrl+F | Фокус в поиск |
| Ctrl+S | Сохранить карточку |
| Esc | Закрыть редактор без сохранения |
| Ctrl+Shift+C | Копировать код открытой карточки |

## 4. Технические решения

### Стек

- **Оболочка:** Tauri 2 (окно, иконка, файловый доступ).
- **Ядро:** Rust. SQLite через `rusqlite` (фичи `bundled` и `fts5`), не через
  `tauri-plugin-sql`: логика переноса разбора и сборка FTS-строки живут в Rust, плагин этого
  не даёт.
- **Фронтенд:** React 18 + TypeScript + Vite.
- **UI:** Ant Design 5 (тёмная тема из коробки).
- **Запросы:** TanStack Query для вызовов Rust-команд.
- **Редактор:** CodeMirror 6 (`@codemirror/lang-python`, `lang-javascript`, `lang-sql`,
  `lang-html`, `lang-css`, `lang-markdown`, `lang-json`, и `lang-legacy` для shell).
- **Патчи строк:** crate `similar`.
- **FTS5:** встроен в `rusqlite` при конфигурации `bundled` + feature `fts5`.

Почему не `tauri-plugin-sql`: он гоняет SQL из фронтенда в SQLite и не даёт серверной
логики. Нам нужно в Rust считать переносы строк и собирать FTS-строку. Много SQL прямо в
React-компонентах ещё и делает невозможным нормальное тестирование.

### Контракт Rust-команд (окончательный)

Все структуры сериализуются `serde` в camelCase.

```
cards_list(filter: Filter) -> Vec<CardSummary>
card_get(id) -> CardDetail
card_save(detail: CardDetail, force: bool) -> SaveResult
card_delete(id)
card_toggle_favorite(id)

tag_list() -> Vec<TagWithCount>
card_set_tags(card_id, tags: Vec<String>)

collection_list() -> Vec<CollectionNode>          // дерево
collection_save(id: Option<i64>, name, parent_id) -> i64
collection_delete(id)
collection_set_cards(collection_id, card_ids: Vec<i64>)
collection_add_card(collection_id, card_id)

search(query: String, filter: Filter) -> Vec<CardSummary>   // со сниппетами

backup_export_json(path) -> Stats
backup_import_json(path) -> ImportReport
backup_export_markdown(card_id, path)
backup_run()                                       // ручная копия базы
```

`card_save` возвращает:

```ts
type SaveResult =
  | { status: "ok" }
  | { status: "needs_confirmation"; summary: { moved: number; changed: number; lost: number } };
```

Первый вызов возвращает `needs_confirmation`, фронтенд показывает окно, второй вызов с
`force: true` сохраняет.

## 5. Этапы разработки

Каждый этап заканчивается работоспособным приложением. Идти строго по порядку: следующий
этап не начинается, пока не собран предыдущий.

### Этап 0. Окружение и каркас (полдня)

1. Проверить `rustc --version` и `cargo --version`; тулчейн по умолчанию должен быть
   `x86_64-pc-windows-msvc`.
2. `npm create tauri-app@latest` - React + TypeScript, перенести в `code-cards/`. Либо
   вручную: Vite, затем `npm i -D @tauri-apps/cli` и `npx tauri init`.
3. `npm install`, `npm run tauri dev` - открывается пустое окно.
4. Добавить зависимости: `antd`, `@tanstack/react-query`, `@codemirror/*`, `similar` в
   `Cargo.toml`.
5. Проверить сборку `rusqlite` с `bundled` и `fts5`: `cargo build` в `src-tauri/`. Первая
   сборка идёт несколько минут, это нормально.
6. README с командами запуска, `.gitignore` (`node_modules`, `target`, `data/`, `dist`).

**Готово, если:** окно открывается, есть заголовок, в логе Rust видна версия SQLite.

### Этап 1. Хранилище и карточки (1-2 дня)

1. Модуль `db`: открытие файла, `PRAGMA journal_mode=WAL`, `foreign_keys=ON`, применение
   схемы из раздела 3.1 с проверкой `schema_meta.version`.
2. Команды `cards_list`, `card_get`, `card_save`, `card_delete`.
3. Список карточек в сетке; создание; редактирование названия и описания.
4. Один блок кода: CodeMirror с нумерацией, выбор языка, сохранение.
5. Копирование кода в буфер.

**Готово, если:** карточку с кодом можно создать, закрыть приложение, открыть и найти её.

### Этап 2. Разбор по строкам (1-2 дня) - ядро

1. Команды для разбора: создать, изменить, удалить диапазон.
2. Панель разбора рядом с кодом, двусторонняя подсветка строк.
3. Кнопка "Разбить на строки": только непустые строки, без строк из одного отступа.
4. **`line_diff.rs`: перенос диапазонов при правке через `similar` плюс сводка
   подтверждения.**
5. Тесты Rust на перенос:
   - вставка строк в начале: все сдвигаются, ничего не теряется;
   - удаление разобранной строки: пояснение становится `is_stale`, не удаляется;
   - полная замена кода: все `is_stale`, количество записей прежнее;
   - код не менялся: ничего не помечено.

**Готово, если:** все четыре теста проходят, перед сохранением в интерфейсе видна сводка.

### Этап 3. Теги (полдня)

1. `tag_list` и `card_set_tags`; нормализация ввода; `COLLATE NOCASE` на `tags.name`.
2. `TagInput` с автодополнением и предупреждением о похожем существующем теге.
3. Фильтр по тегу со счётчиками.

**Готово, если:** тег создаётся один раз, переиспользуется в других карточках, фильтр работает.

### Этап 4. Поиск (1 день)

1. Индексирование в FTS внутри `card_save`.
2. `search` с нормализацией (раздел 3.2) и `snippet()`.
3. Живой поиск в интерфейсе, подсветка совпадений.
4. Фильтры: язык, теги, подборка, избранное.

**Готово, если:** находится и по названию, и по тегу, и по коду (`lru_cache`, `arr[0]`), и по
тексту разбора. Запрос `arr[0]` возвращает карточку с такой строкой - это проверка
нормализации, без неё этап не принимается.

### Этап 5. Подборки (1 день)

1. CRUD дерева, перетаскивание карточек, порядок через `collection_cards.sort_order`.
2. Добавление карточки из самой карточки и из списка.
3. Панель слева с деревом; переход по подборке фильтрует список.

**Готово, если:** создаётся вложенная подборка, в ней меняется порядок, карточка лежит в двух
подборках одновременно.

### Этап 6. Слоты и чертежи (1-2 дня)

2. Галочка "использует слоты", подсветка слотов в редакторе.

4. Форма заполнения, подстановка, копирование результата.

**Готово, если:** карточка с двумя слотами заполняется и отдаёт правильный код; карточка без
слотов не показывает форму, даже если в тексте есть `{{ }}`, при выбранном режиме "не слоты".

**Готово, если:** установщик ставится и запускается; экспорт JSON импортируется обратно без

## 6. Правила для агента-исполнителя

1. **Не перепроектировать.** Все спорные решения приняты в разделе 2. Если спецификация
   противоречит сама себе - сообщить, а не выбирать молча.
2. **Не расширять функционал.** Никаких ИИ-разборов, синхронизаций, аккаунтов, мобильной
   версии. Приложение полностью локальное, без сетевых запросов.
3. **Один этап - один законченный результат.** После каждого этапа приложение запускается и
   работает.
4. **SQL живёт в Rust, не в React.** Фронтенд не знает про SQLite, только про команды.
5. **Молча терять разбор запрещено.** Подтверждение переноса из этапа 2 обязательно. Лучше
   показать лишнюю сводку, чем потерять пояснения.
6. **Данные пользователя неприкосновенны.** Миграции только вперёд, старая база сохраняется.
   Удаление `data/` только с явного разрешения пользователя.
7. **Честно сообщать о блокерах.** Если сборка Rust падает из-за окружения - приводить точную
   ошибку, а не обходить костылями.
8. **Проверять каждый этап руками.** Написать, какие действия выполнил и что увидел. Не писать
   "готово" без проверки.
9. **Комментарии в коде и интерфейс на русском**, идентификаторы на английском. Длинное тире
   не использовать, только короткое.

## 7. Блокеры и риски

| Риск | Что делать |
|---|---|
| Visual Studio 2026 и Rust: сборка через `find-msvc-tools` поддерживает VS 2026 только начиная с Rust 1.93 | После установки проверить версию, при старой сделать `rustup update stable` |
| MSVC не найден после установки ворклоада | Проверить `cl` в "x64 Native Tools Command Prompt", перезапустить терминал и машину |
| Visual Studio стоит нестандартно, в `D:\raznoe\VS2022` | Rust ищет её через `vswhere`; если не находит, указать путь переменной среды |
| Первая сборка Tauri идёт 5-15 минут | Это нормально, не считать зависанием |
| FTS5 выключен в `rusqlite` | Брать фичи `bundled` и `fts5`, проверить тестом на этапе 4 |
| Перенос разбора ошибается на нечётких случаях | Не гадать: при сомнении ставить `is_stale`, сводка покажет расхождение |
| Копия базы в режиме WAL | Использовать `VACUUM INTO`, а не копирование файла |
